# HOH Interaction Profile 0.1 — scroll, gestures and desktop controls

상태: **설계 명세 / 전체 런타임 적용 전**. [사용자 원문](../sources/user-hoh-interaction-2026-10-07.txt)을
보존하고, 아래 해석·충돌 처리·검증 조건은 AI 작성 설계로 구분한다.
HOH의 기존 콘텐츠·피드·AI·대시보드 식별자를 그대로 사용한다.

## 기본 입력 계약

| 규칙 ID | 입력 / 표현 | 소유 영역과 결과 |
| --- | --- | --- |
| `content-vertical` | 콘텐츠 안의 위·아래 스크롤 | 현재 콘텐츠 내부를 세로로 읽는다. 콘텐츠의 가로 스크롤·가로 페이지 넘김은 제공하지 않는다. |
| `feed-horizontal` | 콘텐츠 탐색 영역의 좌우 스와이프 | 셸이 피드를 이전·다음 콘텐츠로 넘긴다. 왼쪽으로 밀면 다음, 오른쪽으로 밀면 이전이라는 방향 매핑은 이 초안의 설계 선택이다. |
| `bottom-edge-agent` | **화면 아래 끝에서 시작해 위로** 끌기 | AI 프롬프트·대화창을 연다. 현재 콘텐츠를 유지한다. |
| `top-edge-dashboard` | **화면 위 끝에서 시작해 아래로** 끌기 | 앱 메인 대시보드를 콘텐츠 영역에 연다. |
| `dashboard-grid` | 대시보드 | 고정 앱과 즐겨찾기한 콘텐츠를 앱 아이콘 그리드로 표시한다. 설정은 고정 앱 중 하나다. 항목이 많아지면 세로로 스크롤한다. |
| `reaction-glass` | 좋아요·싫어요·댓글·공유 | 콘텐츠 위에 떠 있는 글래스모피즘 조작 UI로 제공한다. |
| `desktop-shortcuts` | 웹·PC의 키보드 단축키 | 피드 이동, AI 호출, 대시보드 열기를 빠르게 실행한다. 제스처 사용을 요구하지 않는다. |
| `desktop-glass-controls` | 넓은 화면의 추가 버튼 | AI 호출과 앱 대시보드 열기를 글래스모피즘 버튼으로 제공한다. |

여기서 **화면 끝**은 HOH가 표시되는 가시 뷰포트의 상·하단 경계다. 긴 콘텐츠 문서의
처음·끝이 아니다. 콘텐츠 스크롤 위치와 무관하게 경계에서 동작을 시작할 수 있어야 한다.
콘텐츠 중간에서 시작한 세로 스크롤은 문서 끝에 도달해도 AI·대시보드 호출로 바뀌지 않는다.
위쪽 경계의 한 번의 아래 방향 제스처가 대시보드 호출이다. 화면 반대편까지 손가락이
도달해야 한다는 조건은 두지 않는다. 인식 거리와 경계 영역의 크기는 후속 구현에서 검증한다.

모바일 AI 창의 기존 `content / split / chat` 상태를 유지한다. 아래에서 끌어올리는 중
중간 높이에 놓으면 위에는 콘텐츠, 아래에는 채팅이 보이는 반화면 상태를 지원한다.
열린 채팅의 손잡이를 아래로 내리면 콘텐츠로 돌아간다. 이 동작은 **화면 상단에서
시작하는 대시보드 제스처**와 시작 영역이 다르다. 채팅 기록 자체는 세로 스크롤한다.
PC·넓은 태블릿의 기본 배치는 왼쪽 콘텐츠와 오른쪽 AI다. 이미 열린 AI를 호출하면
입력창으로 포커스를 옮긴다. 호출만으로 메시지를 전송하거나 콘텐츠를 변경하지 않는다.

## 입력 충돌 처리 — AI 작성 구현 지침

1. 포인터 시작 위치로 후보를 정하고 방향이 확정되면 한 동작만 소유한다. 상·하단
   경계에서 시작한 세로 제스처와 콘텐츠 내부 세로 스크롤을 구분한다. 움직임 도중
   경계를 지나갔다는 이유로 소유권을 바꾸지 않는다.
2. 폼·텍스트 선택·슬라이더·게임 캔버스 등 명시적 조작은 해당 컨트롤이 처리한다.
   이미 컨트롤이 처리하는 드래그가 피드 이동을 동시에 발생시키면 안 된다. 앱의 조작은
   가로 스크롤/페이지 탐색을 추가하는 예외가 아니다. 컨트롤 밖의 탐색 영역과 별도 피드
   버튼으로 이동할 수 있어야 한다. 임의의 렌더러가 셸 전체의 탐색을 가로채지 않는다.
3. 가로로 긴 표·코드·SCADA 화면은 줄바꿈·반응형 배치·요약/상세 뷰 또는 명시적
   프로그램 조작으로 수용한다. 가로 스크롤바를 숨기기만 해서 데이터를 잘라내지 않는다.
   콘텐츠 루트와 중첩 콘텐츠 모두 가로 스크롤 없는 프로파일을 만족해야 한다.
4. 제스처 취소·멀티터치·화면 전환은 아직 확정하지 않은 탐색을 취소한다. 진행 중인
   통화 종료나 저장 확인이 필요하면 기존 호스트 정책을 따른다. 경계 제스처가 이를 우회하지 않는다.
5. 운영체제·브라우저의 전용 경계를 가로채는 데 의존하지 않는다. HOH 내부의 접근 가능한
   경계 영역·손잡이와 버튼을 제공하고, 가상 키보드·안전 영역·화면 크기 변화에 맞춘다.
6. 마우스 휠·트랙패드의 일반 세로 스크롤은 현재 콘텐츠나 채팅을 스크롤한다.
   브라우저의 뒤로 가기나 수평 휠을 임의로 피드 이동에 연결하지 않는다.

## 웹 단축키와 글래스 버튼

아래는 **사용자가 지정하지 않은 키 조합에 대한 구현 제안**이다. 확정된 기본 키나
이미 지원되는 API가 아니다. 호스트는 충돌을 확인하고 재지정·해제와 현재 키 안내를 제공한다.

| 의미적 셸 명령 | 후보 키 | 동등한 화면 조작 |
| --- | --- | --- |
| `feed.previous` / `feed.next` | `Alt+Shift+←` / `Alt+Shift+→` | 이전 / 다음 콘텐츠 버튼 |
| `agent.open` | `Alt+Shift+A` | AI 글래스 버튼; 열기 또는 입력 포커스 |
| `dashboard.open` | `Alt+Shift+D` | 앱 그리드 글래스 버튼 |

입력칸·편집기·한글 IME 조합·컨트롤 고유 키 조작 중에는 전역 단축키가 입력을 빼앗지
않는다. 길게 누른 반복 이벤트로 앱이 연속 전환되지 않게 한다. `Escape`는 최상위
대화상자의 닫기/취소를 우선하며 확인되지 않은 변경을 실행하지 않는다. 버튼에는 이름,
포커스 표시, 현재 사용 가능 상태와 단축키 설명을 제공한다. 키보드로 모든 진입점을 사용할 수 있어야 한다.

반응 UI는 콘텐츠 오른쪽, 즐겨찾기는 왼쪽이라는 기존 배치를 이어간다. 넓은 화면의
AI·대시보드 버튼도 같은 반투명 배경·배경 흐림·테두리·그림자 표현을 사용한다.
콘텐츠 글자와 겹쳐 읽기 어려워지지 않게 하고, 흐림을 사용할 수 없을 때도 불투명 배경으로
기능과 가독성을 유지한다. 버튼과 모바일 손잡이는 충분한 조작 영역을 확보한다.

## 의미·상태·행동 계약과의 연결

제스처·키보드·버튼은 같은 의미적 셸 명령으로 정규화한다. 위의 점 구분 명령 이름은
설계 식별자이며 현재 `ContentAction.id`나 공개 런타임 API에 추가된 값은 아니다.
피드/대시보드 이동은 셸의 화면 상태 변경이고, 콘텐츠 데이터 변경은
[Content Contract](CONTENT_CONTRACT.md)의 선언된 action·권한·revision·실행 결과 계약을 따른다.
AI는 좌표나 CSS 클래스만 추측하는 대신 현재 콘텐츠 ID, 화면/상태 버전, 가능한 행동을 읽는다.
화면을 옮겨도 예전 제안이 새 앱에 적용되어서는 안 된다.

## 현재 구현과 남은 차이

아래는 소스 리비전 `48e79cf`의 읽기 전용 관찰이며, 0.3.1(호스트 아이콘·`accepts`·호스트의 열기·밝은 화면 대비)과 0.3.2(열기 결과·배지·대화 목록 키보드)·0.4.0(`64f7878`, 피드 이어 받기·댓글·반응 수·흘러오는 답)에서 다시 확인했다 — 인용한 줄만 옮겨졌고 상태는 같다. 이번 변경은 문서와 그래프이며
새 제스처나 단축키의 실행 코드를 추가하지 않는다.

| 요구 | 현재 소스에서 확인한 상태 | 필요한 작업 |
| --- | --- | --- |
| 콘텐츠 세로 스크롤만 | `.content-stage`는 `overflow:auto` | 중첩 렌더러까지 세로 전용 보장·가로 데이터 수용 확인 |
| 좌우 피드 | 전용 `#feedGesture` 영역에서만 처리 | 콘텐츠 탐색 영역의 입력 소유권 적용 |
| 하단 경계 AI | `#sheetHandle` 드래그와 반화면 상태 존재 | 뷰포트 하단 시작 영역으로 확장 |
| 상단 경계 대시보드 | `#dashboardGesture` 버튼 클릭/드래그 | 뷰포트 상단 시작 영역으로 확장 |
| 앱 그리드·설정 | 고정 앱·즐겨찾기 그리드, 호스트 제공 설정 앱 | 현재 구조 재사용, 호스트별 제공 확인 |
| 글래스 반응 | 네 반응과 즐겨찾기에 blur·반투명 스타일 존재 | 새 프로파일의 배치·접근성 검사 |
| 웹 단축키 | 전역 키 처리 없음 | 명령 매핑·편집/IME 보호·키 안내 |
| 웹 AI·대시보드 글래스 버튼 | 대시보드 버튼은 있으나 두 진입점의 공통 글래스 계약 미적용 | AI 호출 버튼과 공통 스타일 적용 |

## 검증 조건과 그래프

런타임 구현 후에는 콘텐츠 스크롤 위치를 바꾸어 상·하단 **시작 위치**를 각각 검사한다.
내부 세로 스크롤·가로 피드·컨트롤 드래그가 서로 오작동을 일으키지 않는지, 반화면 채팅,
취소/화면 이동, 앱 그리드, 입력/IME 중 단축키 억제, 버튼·키·제스처의 동일 결과를 확인한다.
현재는 이 실행 적합성을 통과했다고 주장하지 않는다.

[그래프](../graph/interaction-profile.jsonld)는 원문 → 프로파일 → 8개 규칙 → 기존 구성요소·
의미적 명령을 연결하고, 문서와 소스 관찰을 구분한다. 사용자 원문은 `USER_PRIMARY`,
해석과 키 후보는 `SECONDARY_AI`, 소스 감사는 `APPLICATION_OBSERVATION`이다.
[질의](../graph/interaction-questions.json)와 [SHACL](../graph/interaction-shapes.ttl)은
경계·축·대상·출처를 검증하며, 경계 시작을 콘텐츠 scrollTop 조건으로 바꾸는 오류도 거절한다.

```sh
uv run --no-project --with-requirements scripts/requirements-semantic.txt python scripts/validate-semantic-standards.py --interaction
```
