# HOH Interface

**HOH Interface는 실행 가능한 콘텐츠와 AI 명령이 하나의 작업 맥락을 공유하는,
최소한의 AI 네이티브 OS 인터페이스다.**

이 문장은 사용자의 방향을 구체화한 AI 작성 정의다. 사용자는
[첫 명명](../sources/user-hoh-ui-2026-10-06.txt)과
[HOH Interface 정정](../sources/user-hoh-interface-2026-10-06.txt)에서 이름과 방향을 제시했다.
대표 이름은 **HOH Interface**, 앞서 사용한 이름 **HOH UI / HOH GUI**는 별칭으로 유지한다.
그래프의 기존 식별자와 `@hoh/ui` 패키지 식별자도 유지한다.

2026-10-07의 [사용자 보충 원문](../sources/user-hoh-semantic-content-2026-10-07.txt)은
콘텐츠 자체의 시맨틱 의미, AI의 조작 가능성, 사람의 직접 편집을 핵심으로 명시했다.
이를 [HOH Content Contract 0.1](CONTENT_CONTRACT.md)의 의미·상태·행동·변경 구독
계약으로 구체화했다. 규격 초안과 참조 구현이며, 모든 기존 앱의 마이그레이션이나
HSWM 실연결 완료를 뜻하지 않는다.

추가된 [입력 프로파일](INTERACTION_PROFILE.md)은 콘텐츠의 세로 스크롤, 가로 피드,
상·하단 경계에서 시작하는 대시보드·AI 호출을 분리한다. 웹에서는 같은 작업을 단축키와
글래스 버튼으로 제공한다. 사용자 원문·설계 해석·현재 구현 관찰을 별도로 보존한다.

## 최소 구성과 역할

| 구성 | 역할 |
| --- | --- |
| 콘텐츠 영역 | 글·앱·게임·작업 결과를 보고 직접 조작하는 실행 공간 |
| AI 대화 영역 | 현재 콘텐츠를 대상으로 의도와 정밀 작업을 전달하는 명령 공간 |
| 피드 | 다음에 탐색할 콘텐츠를 제안하는 진입 경로 |
| 대시보드 | 고정 앱과 저장한 콘텐츠로 직접 돌아가는 진입 경로 |

화면의 기본 영역은 콘텐츠와 AI 대화 두 개다. 대시보드와 설정도 콘텐츠 영역에서
열린다. 피드 탐색, 대시보드 선택, 에이전트의 작업 결과는 같은 콘텐츠 식별자와
프로그램·상태 계약으로 이어지는 것을 목표로 한다.

## 확장해도 지킬 원칙

1. **같은 대상을 다룬다.** 뷰어·앱 조작·AI 요청은 대상 콘텐츠와 화면 버전을 함께
   식별한다. 예전 앱에서 늦게 완료된 작업이 새로 연 앱을 수정하거나 화면을 바꾸면 안 된다.
2. **화면을 늘리기 전에 앱으로 연결한다.** 새 기능은 등록된 콘텐츠 프로그램과 호스트
   어댑터로 넣는다. 대시보드도 하나의 콘텐츠이며 설정은 그 안의 앱이다.
3. **탐색과 의도적인 작업을 함께 지원한다.** 피드는 발견을 돕고 즐겨찾기·대시보드는
   목적 있는 재방문을 돕는다. 추천이 사용자의 진행 중인 작업을 임의로 대체하지 않는다.
4. **변경 결과를 확인한다.** 저장 성공은 백엔드의 확인 뒤 표시한다. 실패한 AI 요청의
   초안은 남기고, 준비되지 않은 제공자를 준비됐다고 표시하지 않는다.
5. **기기는 달라도 의미는 유지한다.** 모바일의 스와이프·반화면과 PC의 좌우 배치는
   같은 탐색·실행·명령을 제공한다. 데이터와 실행 권한은 각 호스트가 관리한다.

## OS라는 표현의 구현 범위

OS와 닮은 핵심은 **앱으로 들어가고, 상태를 유지하며, 명령을 전달하는 공통 사용 환경**이다.
현재 구현 계층은 브라우저에서 실행되는 인터페이스와 앱 실행 셸이다.
프로세스 관리·드라이버·시스템 자원 관리 같은 OS 하부 기능은 현재 구현 범위 밖이다.

MetaHumotonic의 영속 상태·추천·권한 검사는 참조 백엔드가 제공한다. HSWM·CHU·USL은
호스트가 연결하는 백엔드 구성이고, HSWM 에이전트의 실제 정밀 작업은 아직 `NOT_READY`다.
회사 업무와 MM은 적용 대상이며 각각의 서비스 연결이 필요하다.

## 완성도를 판단하는 질문

- 새로운 앱을 기존 콘텐츠·AI 영역 안에서 실행하고 결과를 저장할 수 있는가?
- 피드로 발견한 앱을 저장하고 대시보드에서 같은 상태로 다시 열 수 있는가?
- 앱을 바꿔도 오래된 비동기 작업이 현재 앱에 영향을 주지 않는가?
- AI의 답변과 실행 결과가 실제 대상·버전·실행 결과에 연결되는가?
- 모바일과 PC에서 같은 작업을 끝낼 수 있는가?

앞의 질문을 실제 앱과 사용자 작업으로 검증하면서 최소 구성을 유지한다.
현재 검증 결과는 [기록](../provenance/verification-interface-0.1.1.json)에 남긴다.
